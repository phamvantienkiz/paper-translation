# ADR-001: Áp Dụng Pipeline Xử Lý Bất Đồng Bộ Trong Tiến Trình Kết Hợp Server-Sent Events (SSE)

**Tầng tài liệu**: Architecture Layer — Architectural Decision Record (ADR)  
**Mã quyết định**: ADR-001  
**Trạng thái**: Accepted (Updated for v3.1 Self-Contained Architecture)  
**Ngày quyết định**: 2026-10-05 (Cập nhật: 2026-10-22)  
**Người quyết định**: System Architect & Lead Engineer  

---

## 1. Bối cảnh & Vấn đề (Context & Problem Statement)

Quy trình xử lý một bài báo khoa học 10 – 25 trang bao gồm các công đoạn tính toán kéo dài từ **15 đến 35 giây**:
1. Chạy mô hình **Indra OCR** trên CPU (ONNX Runtime) để phân tích bố cục 2 cột, thứ tự đọc và tọa độ Bounding Box.
2. Kết xuất ảnh nền từng trang độ phân giải cao (Layer 0) và crop các khối hình ảnh qua `PyMuPDF`.
3. Đóng gói toàn bộ các khối văn bản kèm định danh `[[BLK_XXXX]]` và gọi **Google Gemini API (Single-Call)** để dịch toàn văn.
4. Ánh xạ bản dịch tiếng Việt vào hệ tọa độ chuẩn hóa trong SQLite.

Nếu sử dụng mô hình đồng bộ (Synchronous HTTP Request-Response), kết nối HTTP sẽ bị treo lâu, dễ dẫn tới timeout và làm đơ giao diện người dùng. Đồng thời, vì đây là ứng dụng cá nhân và mã nguồn mở tự vận hành (Self-Contained), việc bắt người dùng cài đặt cụm máy chủ Redis + Celery là rào cản không cần thiết.

---

## 2. Quyết định Kiến trúc (Decision)

Chúng tôi quyết định áp dụng mô hình **In-Process Asynchronous Pipeline (`asyncio`)** kết hợp với **Server-Sent Events (SSE)**:
1. **Phản hồi tức thì (`HTTP 202 Accepted`):** Khi người dùng tải lên PDF hoặc nhập mã arXiv, API tạo bản ghi `paper_sessions` (`status='PENDING'`), kích hoạt background task bất đồng bộ và trả về ngay `session_id`.
2. **Thực thi nền không cần Redis:** Các tác vụ nặng (Indra OCR chạy trong threadpool để không chặn event loop + gọi mạng bất đồng bộ `httpx.AsyncClient` tới Gemini API) được điều phối ngay trong tiến trình Python bằng `asyncio`.
3. **Cập nhật tiến trình thời gian thực qua SSE:** Sử dụng `SSEBroadcaster` trong bộ nhớ (`asyncio.Queue`) để đẩy trạng thái từng pha (`OCR_PROCESSING` $\rightarrow$ `TRANSLATING` $\rightarrow$ `COMPLETED`) tới trình duyệt theo thời gian thực.

---

## 3. Đánh giá Đánh đổi (Trade-Off Analysis: Solves / Worsens / Change it when)

| Tiêu chí | Nội dung chi tiết |
|---|---|
| **What it solves (Giải quyết vấn đề gì)** | - Triệt tiêu 100% nguy cơ HTTP Timeout khi chạy Indra OCR và chờ Gemini dịch toàn bài.<br>- Không cần cài đặt Redis hay Celery; chạy toàn bộ hệ thống chỉ bằng 1 lệnh `uvicorn`.<br>- Hiển thị thanh tiến độ mượt mà theo từng giai đoạn trên Web UI. |
| **What it worsens (Gây ra gánh nặng gì)** | - Cần bọc tác vụ CPU-bound của Indra OCR trong `asyncio.to_thread()` để không làm nghẽn FastAPI event loop.<br>- Nếu tắt đột ngột tiến trình server khi đang dịch dở, tác vụ trong RAM sẽ dừng và cần bấm chạy lại. |
| **Change it when (Thay đổi khi nào)** | Chuyển sang Redis + ARQ/Celery khi triển khai bản Cloud SaaS phục vụ hàng trăm người dùng tải bài báo đồng thời. |
