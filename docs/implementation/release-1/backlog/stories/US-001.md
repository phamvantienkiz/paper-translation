# User Story: US-001 — Tiếp nhận tệp bài báo PDF từ máy cục bộ hoặc tự động tải qua arXiv ID/URL

**Mã Story**: US-001  
**Phiên bản**: 3.1  
**Ánh xạ PRD**: FR-01  
**Ưu tiên**: P0 (Must)  

---

## 1. Mô tả User Story (INVEST)
- **As a** Kỹ sư / Nhà nghiên cứu CNTT & AI
- **I want to** tải lên tệp bài báo PDF từ máy tính hoặc nhập mã/URL arXiv
- **So that** hệ thống lưu trữ an toàn tệp PDF gốc và khởi chạy pipeline Indra OCR + Gemini Single-Call bất đồng bộ.

---

## 2. Acceptance Criteria (Given-When-Then)

### AC-01: Tải lên tệp PDF hợp lệ (Happy Path)
- **Given** người dùng chọn một tệp PDF hợp lệ có dung lượng $\le 50\text{MB}$ và có header `%PDF-`
- **When** gửi `POST /api/v1/ingestion/upload`
- **Then** hệ thống lưu tệp vào `storage/raw_pdfs/{session_id}.pdf`, tạo bản ghi `paper_sessions` (`status='PENDING'`), kích hoạt background pipeline và trả về `202 Accepted` kèm `session_id`.

### AC-02: Tải tự động bài báo từ arXiv ID hoặc URL (Happy Path)
- **Given** người dùng nhập mã arXiv (ví dụ `1706.03762` hoặc `https://arxiv.org/abs/1706.03762`)
- **When** gửi `POST /api/v1/ingestion/arxiv`
- **Then** hệ thống tải tệp PDF từ arXiv, lưu vào `storage/raw_pdfs/{session_id}.pdf` và khởi chạy pipeline xử lý nền.

### AC-03: Từ chối tệp sai định dạng hoặc vượt quá 50MB (Negative Path)
- **Given** tệp tải lên không có magic bytes `%PDF-` hoặc lớn hơn 50MB
- **When** gửi yêu cầu tải lên
- **Then** hệ thống trả về lỗi `400 Bad Request` hoặc `413 Payload Too Large` kèm thông báo rõ ràng.
