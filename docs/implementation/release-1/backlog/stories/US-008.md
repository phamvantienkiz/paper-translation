## 1. User Story Statement

**As an** Độc giả học thuật / Kỹ sư R&D  
**I want to** Xuất toàn bộ bài báo đã dịch ra tệp tài liệu định dạng Markdown (.md) hoặc PDF (.pdf)  
**So that** Tôi có thể lưu trữ ngoại tuyến trên máy tính, chia sẻ với cộng đồng nghiên cứu hoặc in ấn học tập

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy Path — Xuất bản dịch ra tệp Markdown (.md) chuẩn MathJax]
- **Given** Người dùng đang ở màn hình đọc bài báo và bấm nút "Xuất file" $\rightarrow$ chọn định dạng "Markdown (.md)"
- **When** Hệ thống tiến hành tổng hợp tài liệu
- **Then** Tệp Markdown được tải xuống máy tính với tên tệp chuẩn hóa `[Ten-Bai-Bao]-vi.md`
- **And** Nội dung tệp chứa đầy đủ Tiêu đề, Tác giả, Abstract, các mục Heading, các đoạn văn tiếng Việt hoàn chỉnh và toàn bộ công thức toán LaTeX ở cú pháp chuẩn (`$ ... $` và `$$ ... $$`) sẵn sàng kết xuất trên GitHub / Obsidian / Notion

### AC2: [Happy Path — Xuất bản dịch ra tệp PDF (.pdf) chuẩn bố cục học thuật]
- **Given** Người dùng chọn xuất định dạng "PDF (.pdf)"
- **When** Trình kết xuất tài liệu của hệ thống biên dịch bài viết
- **Then** Tệp PDF được tải xuống với định dạng trang chuẩn (A4, căn lề 2 bên, đánh số trang ở chân trang)
- **And** Toàn bộ công thức toán học được hiển thị chuẩn xác, không bị cắt dòng giữa chừng

### AC3: [Negative Path — Xử lý khi quá trình tạo file PDF gặp sự cố]
- **Given** Trình sinh PDF backend gặp lỗi do bài báo quá dài hoặc timeout bộ nhớ
- **When** Quá trình kết xuất PDF thất bại
- **Then** Hệ thống giải phóng bộ nhớ đệm
- **And** Hiển thị thông báo thân thiện: "Không thể tạo tệp PDF vào lúc này do quá tải bộ nhớ. Vui lòng thử xuất tệp Markdown hoặc thử lại sau ít phút."
