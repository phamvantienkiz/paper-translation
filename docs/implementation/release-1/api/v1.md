## 1. Quy Chuẩn Kỹ Thuật Chung (Conventions)

- **Base URL**: `/api/v1`
- **Giao thức**: HTTP/1.1 & HTTP/2, RESTful JSON cho các thao tác CRUD, Server-Sent Events (SSE) cho luồng cập nhật tiến độ thời gian thực.
- **Tiêu chuẩn Khung phản hồi (Envelope Structure)**:
  Mọi API phản hồi dạng JSON đều được bọc trong cấu trúc chuẩn:
  ```typescript
  interface ApiResponse<T> {
    success: boolean;       // true nếu thành công, false nếu có lỗi
    data?: T;               // Dữ liệu nghiệp vụ trả về khi success = true
    message?: string;       // Thông điệp trạng thái thân thiện người dùng
    error?: {               // Chi tiết lỗi khi success = false
      code: string;
      message: string;
      detail?: any;
    };
    request_id?: string;    // UUID truy vết luồng xử lý do middleware sinh ra
  }
  ```
- **Hệ tọa độ Canvas Bất biến**: Mọi tọa độ Bounding Box của khối bố cục (`bbox_norm`) đều được chuẩn hóa về dải tỷ lệ `[0.0 .. 1.0]` theo thứ tự `[x0, y0, x1, y1]`, bảo đảm bất biến khi hiển thị trên các màn hình Retina và mức Zoom khác nhau.

## 3. Đặc Tả Chi Tiết Từng Điểm Cuối (Detailed Endpoint Specs)

### 3.1. Tiếp nhận tệp bài báo (`POST /api/v1/ingestion/upload`)
- **Mục đích**: Nhận tệp PDF hoặc DOCX tải lên từ máy cá nhân, lưu vào đĩa cục bộ, khởi tạo phiên dịch trong DB và kích hoạt pipeline xử lý chạy nền.
- **Content-Type**: `multipart/form-data`
- **Request Body**:
  - `file`: File nhị phân (PDF hoặc DOCX, dung lượng $\le 50$MB).
- **Phản hồi 200 OK**:
  ```json
  {
    "success": true,
    "data": {
      "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "file_name": "attention_is_all_you_need.pdf",
      "source_type": "PDF",
      "status": "PENDING",
      "message": "Tệp đã được tải lên thành công và bắt đầu bóc tách trong nền."
    },
    "message": "Upload thành công",
    "request_id": "req-9a8b7c"
  }
  ```
- **Mã lỗi**: `400 Bad Request` (Định dạng file không hỗ trợ hoặc file rỗng), `500 Server Error`.

### 3.2. Thu thập bài báo từ arXiv (`POST /api/v1/ingestion/arxiv`)
- **Mục đích**: Người dùng nhập đường dẫn bài báo (VD: `https://arxiv.org/abs/1706.03762`) hoặc mã định danh arXiv (VD: `1706.03762`), backend tự động tải tệp PDF về và nạp vào pipeline.
- **Content-Type**: `application/json`
- **Request Body**:
  ```json
  {
    "arxiv_input": "1706.03762"
  }
  ```
- **Phản hồi 200 OK**:
  ```json
  {
    "success": true,
    "data": {
      "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  ```

### 3.6. Theo dõi tiến độ thời gian thực SSE (`GET /api/v1/sessions/{session_id}/progress`)
- **Mục đích**: Cung cấp luồng Server-Sent Events liên tục cập nhật trạng thái pipeline từ OCR bố cục $\rightarrow$ Dịch thuật Gemini $\rightarrow$ Hoàn tất.
- **Content-Type**: `text/event-stream`
- **Giao thức sự kiện**:
  - `event: progress_update`: Phát khi tiến độ thay đổi.
  - `event: completed`: Phát khi hoàn tất toàn bộ pipeline.
  - `event: error`: Phát khi xảy ra lỗi.
  - `event: connected`: Khởi tạo kết nối thành công.
- **Ví dụ luồng bản tin**:
  ```text
  event: progress_update
  data: {"session_id":"3fa85f64","status":"OCR_PROCESSING","step":"OCR_PROCESSING","progress_percent":30,"message":"Đang kết xuất ảnh nền Layer 0 (15 trang)..."}

  event: progress_update
  data: {"session_id":"3fa85f64","status":"TRANSLATING","step":"TRANSLATING","progress_percent":75,"message":"Đang dịch toàn bộ bài báo trong 1 lần gọi qua Google Gemini API..."}

  event: completed
  data: {"session_id":"3fa85f64","status":"COMPLETED","step":"COMPLETED","progress_percent":100,"message":"Hoàn tất! Sẵn sàng tái hiện bài báo trên HTML Canvas."}
  ```

### 3.7. Phục vụ tài nguyên hình ảnh & Xuất PDF
- **`GET /api/v1/assets/pages/{session_id}/{filename}`**:
  - Trả về tệp ảnh PNG (`image/png`) 200 DPI độ nét cao của toàn bộ trang gốc (làm Layer 0 cho Canvas).
- **`GET /api/v1/assets/figures/{session_id}/{filename}`**:
  - Trả về tệp ảnh PNG crop riêng hình vẽ/sơ đồ đồ thị.
- **`GET /api/v1/export/{session_id}/pdf`**:
  - Trả về tệp PDF bản dịch hoàn chỉnh (`application/pdf`) do backend kết xuất tự động.

### 3.8. Truy vấn trạng thái Engine dịch thuật (`GET /api/v1/system/engine-status`)
- **Mục đích**: Cung cấp thông tin thời gian thực về Engine đang hoạt động (Local LLM vs Cloud API), kích thước context window, giới hạn trần RAM và trạng thái nạp bộ nhớ cho Frontend hiển thị Badge trên Header.
- **Phản hồi 200 OK**:
  ```json
  {
    "active_provider": "llama_cpp",
    "is_local": true,
    "model_name": "Qwen3-1.7B-Q4_K_M.gguf",
    "context_window": 8192,
    "hard_ram_ceiling_gb": 4.0,
    "estimated_ram_usage_gb": 2.8,
    "ocr_loaded": false,
    "llm_loaded": true
  }
  ```

---

### 3.9. Chuyển đổi Engine dịch thuật (`POST /api/v1/system/engine-switch`)
- **Mục đích**: Cho phép người dùng chuyển đổi runtime giữa Local LLM (llama.cpp) và Cloud API (Gemini/OpenAI). Rào chắn bắt buộc kiểm tra `context_window <= 16384` để bảo vệ trần cứng 4.0GB RAM.
- **Content-Type**: `application/json`
- **Request Body**:
  ```json
  {
    "provider": "llama_cpp",
    "context_window": 8192
  }
  ```
- **Phản hồi 200 OK**: Trả về `EngineStatusResponse` đã cập nhật.
- **Mã lỗi**:
  - `400 Bad Request`: Provider không hợp lệ hoặc `context_window > 16384` (vượt trần cứng 4.0GB RAM).
